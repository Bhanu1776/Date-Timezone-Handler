# Date Format Configuration Guide

This application uses a centralized date format configuration system that allows you to change the date/time format across the entire application by modifying a single file.

---

## 🎯 Quick Start

### Change to US Format (MM/DD/YYYY)

Open `src/config/dateFormat.ts` and modify:

```typescript
export const APP_DATE_FORMAT_CONFIG = {
  DATE_FORMAT: DATE_FORMAT_PRESETS.US,           // MM/dd/yyyy
  TIME_FORMAT: TIME_FORMAT_PRESETS["12H"],       // h:mm a
  DATETIME_FORMAT: DATETIME_FORMAT_PRESETS.US_12H,  // MM/dd/yyyy h:mm a
  DATETIME_LONG_FORMAT: DATETIME_FORMAT_PRESETS.LONG_US_12H,
  INPUT_DATE_FORMAT: DATE_FORMAT_PRESETS.US,
};
```

**Result**: All dates will display as `10/19/2025 3:30 PM`

### Change to European Format (DD/MM/YYYY)

```typescript
export const APP_DATE_FORMAT_CONFIG = {
  DATE_FORMAT: DATE_FORMAT_PRESETS.EU,           // dd/MM/yyyy
  TIME_FORMAT: TIME_FORMAT_PRESETS["24H"],       // HH:mm
  DATETIME_FORMAT: DATETIME_FORMAT_PRESETS.EU_24H,  // dd/MM/yyyy HH:mm
  DATETIME_LONG_FORMAT: DATETIME_FORMAT_PRESETS.LONG_EU_24H,
  INPUT_DATE_FORMAT: DATE_FORMAT_PRESETS.EU,
};
```

**Result**: All dates will display as `19/10/2025 15:30`

### Change to ISO Format (YYYY-MM-DD)

```typescript
export const APP_DATE_FORMAT_CONFIG = {
  DATE_FORMAT: DATE_FORMAT_PRESETS.ISO,          // yyyy-MM-dd
  TIME_FORMAT: TIME_FORMAT_PRESETS["24H"],       // HH:mm
  DATETIME_FORMAT: DATETIME_FORMAT_PRESETS.ISO_24H,  // yyyy-MM-dd HH:mm
  DATETIME_LONG_FORMAT: DATETIME_FORMAT_PRESETS.LONG_US_12H,
  INPUT_DATE_FORMAT: DATE_FORMAT_PRESETS.ISO,
};
```

**Result**: All dates will display as `2025-10-19 15:30`

## 📋 Available Presets

### Date Format Presets

```typescript
DATE_FORMAT_PRESETS = {
  US: "MM/dd/yyyy",          // 10/19/2025
  EU: "dd/MM/yyyy",          // 19/10/2025
  ISO: "yyyy-MM-dd",         // 2025-10-19
  LONG_US: "MMMM d, yyyy",   // October 19, 2025
  LONG_EU: "d MMMM yyyy",    // 19 October 2025
  SHORT_US: "M/d/yy",        // 10/19/25
  SHORT_EU: "d/M/yy",        // 19/10/25
}
```

### Time Format Presets

```typescript
TIME_FORMAT_PRESETS = {
  "12H": "h:mm a",           // 3:30 PM
  "24H": "HH:mm",            // 15:30
  "12H_SECONDS": "h:mm:ss a",  // 3:30:45 PM
  "24H_SECONDS": "HH:mm:ss",   // 15:30:45
}
```

### DateTime Format Presets

```typescript
DATETIME_FORMAT_PRESETS = {
  US_12H: "MM/dd/yyyy h:mm a",        // 10/19/2025 3:30 PM
  US_24H: "MM/dd/yyyy HH:mm",         // 10/19/2025 15:30
  EU_12H: "dd/MM/yyyy h:mm a",        // 19/10/2025 3:30 PM
  EU_24H: "dd/MM/yyyy HH:mm",         // 19/10/2025 15:30
  ISO_12H: "yyyy-MM-dd h:mm a",       // 2025-10-19 3:30 PM
  ISO_24H: "yyyy-MM-dd HH:mm",        // 2025-10-19 15:30
  LONG_US_12H: "MMMM d, yyyy 'at' h:mm a",  // October 19, 2025 at 3:30 PM
  LONG_EU_24H: "d MMMM yyyy 'at' HH:mm",    // 19 October 2025 at 15:30
}
```

## 🔧 Configuration Options

### 1. DATE_FORMAT
Controls how dates are displayed throughout the app (without time).

**Used in**: Event cards, lists, date-only displays

**Example**:
```typescript
DATE_FORMAT: DATE_FORMAT_PRESETS.US,  // 10/19/2025
```

### 2. TIME_FORMAT
Controls how times are displayed throughout the app (without date).

**Used in**: Time-only displays, duration displays

**Example**:
```typescript
TIME_FORMAT: TIME_FORMAT_PRESETS["12H"],  // 3:30 PM
```

### 3. DATETIME_FORMAT
Controls how date and time are displayed together.

**Used in**: Event cards (main display), event lists

**Example**:
```typescript
DATETIME_FORMAT: DATETIME_FORMAT_PRESETS.US_12H,  // 10/19/2025 3:30 PM
```

### 4. DATETIME_LONG_FORMAT
Controls the long format for detailed date/time displays.

**Used in**: Detailed event views, tooltips, extended information

**Example**:
```typescript
DATETIME_LONG_FORMAT: DATETIME_FORMAT_PRESETS.LONG_US_12H,
// October 19, 2025 at 3:30 PM
```

### 5. INPUT_DATE_FORMAT
Controls the format shown in form inputs (currently informational).

**Note**: HTML `datetime-local` inputs always use `yyyy-MM-ddTHH:mm` format internally, but this setting documents your preferred display format.

## 🎨 Custom Formats

### Creating a Custom Format

You can create your own custom format using date-fns format strings:

```typescript
export const APP_DATE_FORMAT_CONFIG = {
  DATE_FORMAT: "EEE, MMM d, yyyy",     // Wed, Oct 19, 2025
  TIME_FORMAT: "h:mm:ss a",            // 3:30:45 PM
  DATETIME_FORMAT: "EEE, MMM d, yyyy 'at' h:mm a",
  DATETIME_LONG_FORMAT: "EEEE, MMMM d, yyyy 'at' h:mm:ss a",
  INPUT_DATE_FORMAT: "MM/dd/yyyy",
};
```

### Date-fns Format Tokens

Common tokens you can use:

| Token  | Example   | Description             |
| ------ | --------- | ----------------------- |
| `yyyy` | 2025      | 4-digit year            |
| `yy`   | 25        | 2-digit year            |
| `MMMM` | October   | Full month name         |
| `MMM`  | Oct       | Short month name        |
| `MM`   | 10        | 2-digit month           |
| `M`    | 10        | Month (no leading zero) |
| `dd`   | 19        | 2-digit day             |
| `d`    | 19        | Day (no leading zero)   |
| `EEEE` | Wednesday | Full day name           |
| `EEE`  | Wed       | Short day name          |
| `HH`   | 15        | 24-hour (00-23)         |
| `H`    | 15        | 24-hour (0-23)          |
| `hh`   | 03        | 12-hour (01-12)         |
| `h`    | 3         | 12-hour (1-12)          |
| `mm`   | 30        | Minutes                 |
| `ss`   | 45        | Seconds                 |
| `a`    | PM        | AM/PM                   |

**Full reference**: [date-fns format documentation](https://date-fns.org/docs/format)

## 💡 How It Works

### Architecture

The application uses a **centralized configuration** approach:

```
src/config/dateFormat.ts (SINGLE SOURCE OF TRUTH)
         ↓
src/utils/timezone.ts (reads config)
         ↓
src/hooks/useDateTimeConverter.ts (uses utilities)
         ↓
src/components/*.tsx (uses hooks/utilities)
```

### Automatic Application

When you change the config, **all components automatically** use the new format:

1. ✅ EventCard component
2. ✅ EventList component
3. ✅ TimezoneDisplay component
4. ✅ Any custom components using the utilities

**No code changes needed in components!**

## 🚀 Usage in Code

### In Components

```typescript
import { formatEventDateTime } from "@/utils/timezone";

// Automatically uses app config format
const formatted = formatEventDateTime(utcDate, timezone);
// Result: "10/19/2025 3:30 PM" (if US format configured)
```

### With Custom Hook

```typescript
import { useDateTimeConverter } from "@/hooks/useDateTimeConverter";

function MyComponent() {
  const { formatDateTime, formatDate, formatTime } = useDateTimeConverter();
  
  // All use app config formats
  const dateTime = formatDateTime(utcDate, timezone);
  const dateOnly = formatDate(utcDate, timezone);
  const timeOnly = formatTime(utcDate, timezone);
}
```

### Override Format (When Needed)

```typescript
// Use app config format
const formatted = formatEventDateTime(utcDate, timezone);

// Override with custom format
const customFormatted = formatEventDateTime(
  utcDate, 
  timezone, 
  "yyyy-MM-dd HH:mm:ss"
);
```

## 🎯 Best Practices

### 1. Consistent Format Choice

Choose formats that match your:
- Target audience location
- Company standards
- Industry standards
- User preferences

### 2. Date Format Selection

**US Format** (`MM/dd/yyyy`):
- ✅ US-based users
- ✅ US-based companies
- ❌ International audience (can be confusing)

**European Format** (`dd/MM/yyyy`):
- ✅ European users
- ✅ Most of world except US
- ❌ US users (can be confusing)

**ISO Format** (`yyyy-MM-dd`):
- ✅ International audience
- ✅ Unambiguous
- ✅ Sortable
- ✅ Technical contexts
- ⚠️ Less familiar to casual users

### 3. Time Format Selection

**12-hour** (`h:mm a`):
- ✅ US, Canada, Australia, Philippines
- ✅ Familiar to non-technical users
- ❌ Takes more space

**24-hour** (`HH:mm`):
- ✅ Most of world
- ✅ Military/technical contexts
- ✅ Compact
- ❌ Less familiar in US

### 4. Testing

Always test format changes with:
- Different timezones
- Edge cases (midnight, DST transitions)
- All parts of the application

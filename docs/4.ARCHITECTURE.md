## 2. Create Event Flow

```
Step 1: User Input
┌─────────────────────────────────────────┐
│  User in India (Asia/Kolkata)           │
│  Enters: Jan 15, 2025, 10:00 AM         │
│  (datetime-local shows in local time)   │
└──────────────────┬──────────────────────┘
                   │
                   ▼
Step 2: Frontend Processing
┌─────────────────────────────────────────┐
│  Detect Timezone:                       │
│  Intl.DateTimeFormat()                  │
│    .resolvedOptions()                   │
│    .timeZone                            │
│  → "Asia/Kolkata"                       │
│                                         │
│  Prepare Payload:                       │
│  {                                      │
│    startDateTime: "2025-01-15T10:00",  │
│    timezone: "Asia/Kolkata"            │
│  }                                      │
└──────────────────┬──────────────────────┘
                   │
                   ▼
Step 3: API Receives
┌─────────────────────────────────────────┐
│  POST /api/events                       │
│                                         │
│  Received:                              │
│  {                                      │
│    startDateTime: "2025-01-15T10:00",  │
│    timezone: "Asia/Kolkata"            │
│  }                                      │
└──────────────────┬──────────────────────┘
                   │w
                   ▼
Step 4: Convert to UTC
┌─────────────────────────────────────────┐
│  Using date-fns-tz:                     │
│                                         │
│  const localDate = new Date(            │
│    "2025-01-15T10:00"                   │
│  );                                     │
│                                         │
│  const utcDate = fromZonedTime(         │
│    localDate,                           │
│    "Asia/Kolkata"                       │
│  );                                     │
│                                         │
│  utcDate.toISOString()                  │
│  → "2025-01-15T04:30:00.000Z"          │
│                                         │
│  (10:00 AM IST = 4:30 AM UTC)          │
└──────────────────┬──────────────────────┘
                   │
                   ▼
Step 5: Store in Database
┌─────────────────────────────────────────┐
│  events.json:                           │
│  {                                      │
│    "startDateTime":                     │
│      "2025-01-15T04:30:00.000Z",       │
│    "timezone": "Asia/Kolkata"          │
│  }                                      │
│                                         │
│  ✓ Stored in UTC                        │
│  ✓ Original timezone preserved          │
└─────────────────────────────────────────┘
```

## 5. Hook Dependencies

```
useTimezone()
│
├── Uses: Intl API
├── Returns: { timezone, isLoading, error }
└── No dependencies

useDateTimeConverter()
│
├── Uses: date-fns-tz functions
├── Returns: { convertUTCToLocal, convertLocalToUTC, ... }
└── Memoized for performance

useEvents()
│
├── Depends on: fetch API
├── Returns: { events, createEvent, updateEvent, deleteEvent, ... }
├── Features:
│   ├── Optimistic updates
│   ├── Error handling
│   └── Auto-refresh
└── State management with useState
```

## 6. Timezone Conversion Process

```
Local DateTime String (from input)
        "2025-01-15T10:00"
                │
                ▼
        new Date() constructor
                │
                ▼
        JavaScript Date object
        (interpreted in system timezone)
                │
                ▼
        fromZonedTime(date, timezone)
        (date-fns-tz function)
                │
                ▼
        UTC Date object
                │
                ▼
        toISOString()
                │
                ▼
        ISO 8601 UTC string
        "2025-01-15T04:30:00.000Z"
                │
                ▼
        Store in database
```

## 7. API Request/Response Flow

### Create Event

```
REQUEST:
POST /api/events
Content-Type: application/json

{
  "title": "Team Meeting",
  "description": "Quarterly review",
  "startDateTime": "2025-01-15T10:00",
  "endDateTime": "2025-01-15T11:00",
  "timezone": "Asia/Kolkata",
  "createdBy": "John"
}

↓ API converts to UTC ↓

RESPONSE:
{
  "success": true,
  "data": {
    "id": "123e4567-e89b-12d3-a456-426614174000",
    "title": "Team Meeting",
    "description": "Quarterly review",
    "startDateTime": "2025-01-15T04:30:00.000Z",  ← UTC
    "endDateTime": "2025-01-15T05:30:00.000Z",    ← UTC
    "timezone": "Asia/Kolkata",
    "createdBy": "John",
    "createdAt": "2025-01-10T12:00:00.000Z"       ← UTC
  }
}
```

### Get Events

```
REQUEST:
GET /api/events

RESPONSE:
{
  "success": true,
  "data": [
    {
      "id": "123e4567-e89b-12d3-a456-426614174000",
      "startDateTime": "2025-01-15T04:30:00.000Z",  ← UTC
      "endDateTime": "2025-01-15T05:30:00.000Z",    ← UTC
      "timezone": "Asia/Kolkata",
      ...
    }
  ]
}

↓ Frontend converts to user's timezone ↓

DISPLAYED:
"Jan 15, 2025 at 10:00 AM" (if user is in Asia/Kolkata)
"Jan 14, 2025 at 8:30 PM"  (if user is in America/Los_Angeles)
"Jan 15, 2025 at 4:30 AM"  (if user is in Europe/London)
```

## 8. State Management Flow

```
useEvents Hook State:
┌────────────────────────────────────┐
│ events: Event[]                    │
│ isLoading: boolean                 │
│ error: string | null               │
└────────────────────────────────────┘
                │
                ├──► createEvent()
                │    ├─ Optimistic: add to state
                │    ├─ API call
                │    └─ On success: keep | On error: revert
                │
                ├──► updateEvent()
                │    ├─ Optimistic: update in state
                │    ├─ API call
                │    └─ On success: keep | On error: revert
                │
                └──► deleteEvent()
                     ├─ Optimistic: remove from state
                     ├─ API call
                     └─ On success: keep | On error: refetch
```

## Key Architectural Decisions

### 1. UTC Storage
**Why**: Single source of truth, no ambiguity
**How**: Convert all inputs to UTC before storing

### 2. IANA Timezones
**Why**: Handles DST automatically, unambiguous
**How**: Use Intl API for detection, date-fns-tz for conversion

### 3. Native datetime-local Input
**Why**: Consistent UX, browser-native, no library needed
**How**: Attach timezone separately on submission

### 4. Optimistic Updates
**Why**: Better UX, feels instant
**How**: Update state immediately, revert on error

### 5. Reusable Utilities
**Why**: Portability, maintainability, testability
**How**: Pure functions, no app-specific logic
